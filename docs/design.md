## 1. 全体像

FontMemo は1画面の Web アプリ。要件の処理は1本のパイプラインに集約する。

```
文章入力＋設定
  → レイアウト（折り返し・寸法確定・上限チェック）
  → 描画（白背景・黒文字、AA あり）
  → 二値化（大津法）
  → プレビュー表示（欠字マーカー重畳）＋ PNG Blob を生成して保持
  → 保存／共有は、保持した Blob をそのまま使う
```

PNG Blob をプレビュー時点で作っておくのは、Web Share API の制約（ユーザー操作直後の短い間しか共有を呼び出せない）のため。共有ボタンの押下後に重い生成処理を挟まない。

端から端までの流れ（通常モード）：

1. ユーザーが文章を入力し、フォント・文字サイズ・幅プリセットを選ぶ
2. 入力のたびにレイアウトが再計算され、プレビューと PNG Blob が更新される（デバウンス 150ms）
3. 欠字があれば、プレビューの該当文字にマーカーが付き、警告バーに文字が列挙される
4. 「保存」でダウンロード、「共有」で共有シート（対応環境のみボタン有効）

技術スタックは他アプリと揃える：TypeScript ＋ Vite、静的ホスティング、PWA（manifest ＋ Service Worker）。Rust コアは持たない（画像処理は Canvas と画素処理で足りる）。

### 主要な関数表面

**fonts/cmap.ts**

- `parseCmap(buf: ArrayBuffer): Coverage | null` — sfnt の cmap テーブルから収録文字の範囲列を返す。サブテーブルは format 12（platform 3, encoding 10）を優先し、format 4（3,1）、format 6 の順に探す。**範囲内にあるだけでは収録とせず、対応グリフ ID が 0（.notdef）でない文字だけを収録とする**（format 4 はグリフ配列、format 12 はグループの開始グリフ ID を実際に引く）。TTC は先頭フェイスの cmap を使う。WOFF/WOFF2 では null（v1 では収録判定の対象外、§8-2）
- `covers(cov: Coverage, cp: number): boolean` — 二分探索で判定
- `missingChars(cov: Coverage, text: string): string[]` — 文章中の未収録文字を重複なしで返す

**fonts/fontMeta.ts**

- `sniffFormat(buf: ArrayBuffer): 'ttf' | 'otf' | 'ttc' | 'woff' | 'woff2' | null` — 先頭バイトと sfnt 構造から形式を判定する。拡張子は信用しない（ZIP 取り込みの検証にも使う）
- `fontDisplayName(buf: ArrayBuffer): string | null` — name テーブル（nameID 4、なければ 1）から表示名を取る。日本語レコードを優先する

**fonts/fontStore.ts**

- `importFonts(file: File): Promise<ImportResult>` — 取り込みの入口。ZIP なら `extractFontCandidates` で候補を出し、単体ファイルならそのまま、候補ごとに `addFont` を呼ぶ
- `addFont(blob: Blob): Promise<FontRecord>` — 形式検証 → 名前抽出 → cmap 解析 → 内容ハッシュで重複確認 → IndexedDB 保存
- `listFonts(): Promise<FontRecord[]>` ／ `deleteFont(id: string): Promise<void>`
- `FontRecord = { id, name, format, blob, coverage: Coverage | null, hash, createdAt }`（hash は SHA-256。重複判定はファイル名でなく内容で行う）
- `ImportResult = { added: FontRecord[], skipped: { name, reason }[] }`、reason は `'not-font' | 'duplicate' | 'too-large' | 'unreadable'`。フォントが1件も見つからない場合は、その旨を理由付きで UI に返す

**fonts/unzip.ts**

- `extractFontCandidates(file: File): Promise<{ name: string, blob: Blob }[]>` — fflate で非同期に解凍し、フォント候補だけを返す。実装条件は §8-1

**fonts/loader.ts**

- `ensureLoaded(rec: FontRecord): Promise<void>` — 内部ファミリー名 `fm-<id>` で FontFace を登録（端末フォントとの名前衝突を避けるため、表示名と内部名を分ける）。**起動時に全フォントを読み込まない**。選択されたとき・見本を描くときに、そのフォントだけを読み込む
- `fontStack(rec: FontRecord | null): string` — Canvas 用 font-family 文字列。選択フォント → OS 標準の日本語フォント候補 → sans-serif の順（FR-02 のフォールバックチェーン）

**core/layout.ts**（レイアウトはフォント解析に依存しない。欠字判定は cmap.ts、マーカー位置計算はレイアウト結果と欠字集合から別関数で行う）

- `layoutText(text: string, opts: LayoutOptions): LayoutResult`
- `LayoutOptions = { fontStack, fontSize, lineHeightFactor, wrapWidth: number | null, margins, align, mode: 'normal' | 'sideways' }`（wrapWidth が null のとき改行のみで分割＝横モードの行）
- `LayoutResult = { ok: true, lines: LaidLine[], width, height } | { ok: false, reason: 'too-long' | 'block-too-tall' }`
- `LaidLine = { text, width, x, charOffsets: number[] }`（charOffsets はコードポイント単位の開始位置。文字幅の測定は共有のオフスクリーン Canvas の `measureText` で行う）
- `missingMarks(layout: LayoutResult, missing: Set<string>): MissingMark[]` — `MissingMark = { lineIndex, x, width }`。結合文字の並びでは位置が近似になる場合がある（§5.2）

**core/binarize.ts**

- `otsuThreshold(luminance: Uint8ClampedArray): number` — 256 階調ヒストグラムから大津の閾値を返す
- `binarize(src: HTMLCanvasElement): HTMLCanvasElement` — 閾値で黒白に変換した新しい Canvas を返す。輝度が単一（白紙など）の画像は変換せずそのまま返す

**core/caps.ts**

- `platformCaps(): { maxSide: number, maxArea: number }` — 初期値：iOS は maxSide 4,096・maxArea 4,096×4,096、その他は maxSide 8,192・maxArea 8,192×8,192（要件 §11 の実機検証で確定させる）
- `withinCaps(width: number, height: number): boolean` — 長辺と面積の両方を確認する（FR-09）。範囲内でも Canvas 生成に失敗しうるため、生成側は失敗を捕捉して「生成できませんでした」と表示し、処理を止める

**core/saveName.ts**

- `nextSaveName(): string` — `fontmemo-YYYYMMDD-HHMMSS.png`、同一セッションで同名が再生成されたら `-2`、`-3` を付ける（4アプリ共通規則）

**core/share.ts**

- `savePng(blob: Blob, filename: string): void` — ダウンロードで保存する
- `sharePng(blob: Blob, filename: string): Promise<void>` — 共有シートを開く。呼び出しはユーザー操作の直後に行い、生成済み Blob を渡す。非対応環境では共有ボタン自体を無効化し、保存への切替を案内する

## 3. フォント供給の構造

フォントの出所は3層。機能保証の範囲が層ごとに違うことを設計の前提にする。

| 層 | 出所 | 欠字検出 | 備考 |
|---|---|---|---|
| 1（主） | ユーザーが取り込んだフォントファイル（IndexedDB 保存） | cmap 解析で判定（FR-02、保証範囲は §5.2） | このアプリの中心 |
| 2 | OS 標準フォント（名前指定の候補リスト） | 対象外 | 端末により有無が違うため、フォールバック先としてのみ使う |
| 3（v1 見送り） | Local Font Access API で列挙した端末フォント（Chromium のみ、許可制） | 対象外 | §8-4 決定。将来の段階的強化 |

### AnyFont 等でインストールしたフォントについて（調査結果）

iOS の AnyFont は、構成プロファイル経由でフォントを端末に入れるネイティブアプリ。入れたフォントは、OS のフォントピッカーを使うネイティブアプリ（Pages、ピータッチ系アプリ等）でのみ使える。**Safari 上の Web アプリからは、プロファイルで入れたフォントを列挙することも、名前指定で使うこともできない**（Web 開発者による実地確認でも、公開サイトでは使えず、ローカル HTML の表示でのみ使えたと報告されている）。

したがって FontMemo が Web アプリである限り、AnyFont 的な「端末へのインストール」も「インストール済みフォントの利用」も対象外になる。FontMemo の取り込み方式は、同じフォントファイルを FontMemo の中にも保持する形で、実質的に同じ目的（好きなフォントで書く）をプロファイル承認なしに達成する。

## 4. フォント導線（FR-05 の具体化）

fontfree.me には利用可能な API がなく（WordPress の REST API はホスティング側 WAF で遮断され、CORS も返らない）、フォントファイル自体も保持していない（ダウンロードは各作者の配布サイトへのリンク）。よって連携は「導線」として設計する。

フォントピッカーの構成：

1. **取り込み済みフォント** — 各フォント自身の書体で描いた見本（フォント名＋サンプル文字列）で一覧表示する（FR-02）。選ぶ前に字形が分かる。WOFF/WOFF2 のフォントには「欠字チェック対象外」の表示を添える（§8-2）
2. **「フォントを探す」ボタン** — FONT FREE を新規タブで開く。案内文で「見本を見て選ぶ → ダウンロード → ここに戻って取り込む」の3手順を示す
3. **「フォントを取り込む」ボタン** — ファイル選択。**ZIP のまま渡せる**（§8-1）。配布サイトの多くが ZIP 配布のため、解凍をユーザーに強いない。取り込んだフォントは一覧に即表示され、その場で選べる
4. 空状態（取り込みゼロ）では、2と3を大きく見せて最初の1フォントへ誘導する

## 5. 主要アルゴリズム

### 5.1 レイアウトと折り返し

- 通常モード：幅はプリセット（250px／384px（200dpi相当）／576px（300dpi相当）／カスタム、FR-07）で固定し、文章を折り返して高さが伸びる
- 折り返しは文字単位の測定で行い、簡易な禁則処理を入れる。行頭禁則文字（、。・：；！？）」』】等、小書き仮名）は前の行に追い込む（追い込み方式）。行末禁則（「『【等）は次行へ送る。英単語は空白で優先的に割り、行幅より長い単語は途中で割る。明示改行は保持し、空行は1行分の高さを持つ
- 横モード（FR-14）：行は改行でのみ作り、折り返しはしない。読み向きで「幅＝最も長い行の幅、高さ＝行数×行間＋余白」のブロックを組み、ブロック高さが出力幅を超えたら生成を止める（`block-too-tall`）。描画後に90度右回転し、プレビューは回転後の縦長画像を表示する
- 上限チェック：最終画像の寸法（横モードは回転後）で `withinCaps` を確認し、超えたら生成を止めて警告する（`too-long`）。黙って切り捨てる経路は作らない
- 文章が空のときは保存・共有ボタンを無効化する

### 5.2 欠字の検出と表示

- 保証範囲の正確な表現：**「対応する cmap から、文字単位のグリフ収録（グリフ ID が 0 でないこと）を判定する。ただし結合文字・異体字セレクタなど複雑な文字組みの表示保証は対象外」**
- 選択フォントに coverage がある場合のみ、文章の全文字を照合する（コードポイント単位）
- プレビュー：二値化済み画像の上に、欠字位置へアクセントカラーの下線マーカーを重畳する（`missingMarks` の結果を使用）。**マーカーはプレビューだけに描き、出力 PNG には入れない**。警告バーには欠けた文字そのものを列挙する
- 出力 PNG：欠字はフォールバックチェーンの書体で通常描画する（FR-02）

### 5.3 二値化

- 描画は最終解像度で直接行う（拡大描画＋縮小はしない）。AA のグレーから輝度ヒストグラムを作り、大津法で閾値を決めて黒白化する
- 輝度が単一の画像（白紙・全面ベタ）では閾値が定まらないため、二値化をスキップしてそのまま返す
- 大津法と固定閾値128の優劣は要件 §11 の実印刷比較で確定する。実装は閾値決定を差し替え可能な形にしておく

### 5.4 描画と回転

- 描画 Canvas は白背景・黒文字。横モードの回転は画素コピーで90度右回転した Canvas を作る（transform 描画ではなく画素転置に寄せ、出力寸法を厳密にする）。回転前後の2枚が同時に存在する時間があるため、回転が済んだら元の Canvas は速やかに解放する
- Canvas の生成に失敗した場合は例外を捕捉し、「生成できませんでした」と表示して処理を止める（上限範囲内でも失敗しうるため）

## 6. データ

**IndexedDB**（DB 名 `fontmemo-db`、ストア `fonts`）：FontRecord を Blob ごと保存。coverage は範囲列（数値配列）として一緒に保存し、起動時の再解析を不要にする。重複判定は内容ハッシュ（SHA-256）で行う。

**localStorage**（キー `fontmemo-settings`）：選択フォント ID、文字サイズ、行間、余白、揃え、幅プリセット／カスタム幅、モード（通常／横）、UI 言語。文章そのものは保存しない（FR-01）。

**起動時**：保存フォントのメタデータだけを読み、ピッカーを構築する。FontFace 登録は必要時（選択・見本描画）に行う。登録に失敗したフォント（破損等）はピッカーで無効表示にし、削除を促す。

## 7. 保存・共有・PWA・更新

- 保存と共有は別操作として実装する（§2 の savePng／sharePng）。共有用 Blob はプレビュー生成時に用意しておく（§1）
- PWA：manifest と Service Worker（アプリシェルを cache-first）。ただし版ズレ対策として、起動時に version.json を照合し、不一致ならキャッシュを消して読み直す自己修復を入れる（他アプリで実証済みの方式）
- バージョン規則：`appVersion` は GitHub タグ（v を除いたもの）と一致させる。実機確認用は v0.1.0 番代、正式版は v1.0.0 番代
- GitHub Pages のデプロイはタグを契機とする Actions ワークフローで行う

## 8. 決定事項（v0.2 で確定）

### §8-1 ZIP 取り込み：採用（必須機能とする）

配布サイトの多くが ZIP で配るため、ZIP のまま取り込めることが導線の要になる。解凍ライブラリは fflate（非同期解凍を使う）。実装条件：

- 拡張子でなく実データ（マジックバイト＋sfnt 構造）でフォントかどうかを検証する
- 上限（初期値）：走査するエントリ数 512 件まで／候補ファイル 32 件まで／個別ファイルの解凍後サイズ 32MB まで／候補の解凍後合計 96MB まで。超過したら中断し、理由を表示する
- サブディレクトリ内のフォントも検出する
- 同じフォントの重複登録は内容ハッシュで防ぐ
- フォントが見つからなかった場合は、理由（フォントファイルが含まれていない等）を表示する
- 複数フォント入り ZIP は全件取り込み、一覧に即表示してその場で選べるようにする

### §8-2 WOFF/WOFF2 の欠字検出：v1 では対象外

WOFF2 は Brotli 圧縮に加えてフォントテーブルの変換処理があり、TTF/OTF と同じ方法では cmap を読めない。v1 の検出保証は TTF/OTF/TTC に限る。WOFF/WOFF2 の取り込み（描画利用）自体は可能だが、「読み込めること」と「欠字検出できること」は別であり、ピッカーで「欠字チェック対象外」と表示して区別する。

### §8-3 UI の日英切替：採用

`app/i18n.ts` の辞書方式。初期値はブラウザ言語から判定し、手動切替を優先して localStorage に保存する。

### §8-4 Local Font Access：v1 では見送り

`queryLocalFonts()` は許可制でブラウザ対応も限定的であり、主対象であるスマホ利用者への恩恵が小さい。取り込みフォントを主役とする v1 では開発リソースを割かない。将来の段階的強化として、モジュールを追加できる形だけは保つ。

### §8-5 プリインストールフォント：りいポップ角を第1号とする

検討結果は §9 の表を参照。りいポップ角は Web フォントとして同梱し、初期状態から選べるようにする。フォントファイル自体をダウンロードさせる機能は付けない。

## 9. 要件 §11 検証事項との対応

| 検証事項 | 設計での扱い |
|---|---|
| 初回起動時の体験・同梱フォントの可否 | 空状態の導線（§4-4）に加え、プリインストールフォントを1書体用意する（§8-5）。**りいポップ角（あおいりぃ作）は同梱可**：利用規約で Web フォントとしての利用（形式変換も可）とプログラムへの同梱・埋め込みが明示的に許可され、事前連絡も不要。禁止されているのはフォントファイル単体の転載・再配布・販売のため、描画専用の Web フォントとして同梱し、ダウンロード機能は付けない。**あんずもじ（あんずいろapricot）は同梱不可**：作者 FAQ で「アプリへの組み込みは可だが、自サーバーからインストールさせる形は再配布として不可」と明示されており、サーバー配信型の Web アプリは後者に当たる。取り込み機能で対応する |
| cmap 取得のフォーマット別可否 | TTF/OTF/TTC は自前パーサで確定（グリフ ID まで確認）。WOFF/WOFF2 は §8-2 |
| Canvas 上限の実測 | caps.ts のテーブルに切り出し、実測値で差し替える |
| 二値化の実印刷比較 | 閾値決定を差し替え可能に分離（§5.3） |
| 横モードの実機確認 | 回転後の寸法で上限チェック（§5.1）。排出順は実機で確認 |
| プリンタアプリ側の長大画像読み込み制限 | アプリ側では制御不能。判明したら上限テーブルの初期値に反映する |
