# FontMemo 要件定義書 v0.5

**作成日：** 2026年11月19日（v0.1 初版、同日 v0.2／v0.3／v0.3.1 改訂、同日 v0.4 で実装結果を反映、同日 v0.5 で次期大改定の計画を反映）

**大改定（アプリ v0.5.0、2026-11-19 友達ユーザーの実機フィードバックによる。同日実装）：**
- プレビューを廃止し、編集欄がプレビューを兼ねる（FR-08 を改訂）。「入力欄とプレビューで文字の大きさが違う」「プレビューまで移動が長い」という混乱をなくし、入力したままのレイアウトで印刷される形にする
- 編集欄の表示倍率は固定値（×1）をやめ、「印刷幅が画面の表示幅に収まる倍率」を動的に使う。同じ文字サイズでも T02（384px）と M02S（576px）で表示の大きさが変わるのが正しい姿で、倍率は設定項目にしない
- 保存・共有ボタンは編集欄の直下に配置する（v0.3.0 までの「プレビュー直下」から変更）
- 欠字の強調表示は編集欄の中で行う。長すぎ・行ブロック超過の警告はボタンの付近に表示する
- 横印刷では編集欄は読み向きのブロック表示のままとし、高さが紙幅ちょうどに収まる形で示す（回転は出力時）
- 印刷用 PNG は保存・共有の操作時に裏で生成する。レイアウト計算が正本であることは従来どおりで、画質は変わらない
- iPhone で画像の幅セグメント（250px／384px／576px／カスタム＋数値入力）が1行に収まらず崩れる問題を直す。セグメントは折り返し可能とし、カスタム数値入力はセグメントとは別の行に出す

**v0.4 の主な変更（2026-11-19、v0.1.0〜v0.2.9 の実装と実機確認の反映）：**
- 入力方式を WYSIWYG 編集欄に確定した（FR-01）。実際のフォントで書きながら、スマホ標準の文字選択・コピー＆ペーストをそのまま使う。文章欄の表示は「フォントサイズ × 固定倍率（×1）」とし、倍率は設定項目にしない
- 部分書式（FR-16）を追加した。文字の範囲ごとにフォント・大きさ（絶対 px。倍率の概念は持たない）・太字・斜体を指定できる。太字・斜体は、そのフォントに実フェイスがある場合のみ指定できる
- スタイル欄を新設し、常時アクティブとした。範囲未選択時は全体のデフォルト（フォント・文字サイズ・太字・斜体）を編集する。設定カードの文字サイズはスタイル欄へ移設した
- フォント管理（FR-02）を新設した。同梱・取り込み・端末フォントを一覧表示し、行の選択で見本を表示、On/Off でスタイル欄への表示を制御する。削除は取り込みフォントのみ
- 同梱フォント6書体（＋適当ポエムの太字フェイス）を実装した。同梱フォントは選択したときに初めて読み込み、見本はフォント管理で選択時に表示する。欠字検出の保証は同梱フォントにも拡張した（ビルド時に生成する coverage manifest で判定）
- 共有できない環境では、共有ボタンが無言で失敗せず理由を表示する（FR-09。Voice2QR と同じ挙動）
- 保存・共有ボタンはプレビュー直下に配置する。画面下部の固定バーは持たない
**アプリ名：** FontMemo（フォントメモ）
**キャッチコピー：** 好きなフォントで、好きな言葉を。
**開発形態：** 完全クライアントサイドPWA

**v0.3 の主な変更（2026-11-19、レビュー反映。技術的主張は MDN で裏取り済み）：**
- 欠字検出の方式を、取り込んだフォントファイルの `cmap` テーブル解析に変更した。`FontFaceSet.check()` は個別文字のグリフ収録を判定する API ではない（MDN 明記）ため使えない。検出の保証は取り込みフォントに対してのみとし、端末フォントは保証範囲外と明記した（FR-02）
- 出力上限をプラットフォーム別の保守値とした（iOS は Canvas の 4,096px 制限が MDN に明記されている）。上限超過時は切り捨て保存をせず、生成を止めて警告する（FR-09）
- 横印刷モードの行ブロック超過時も、黙って欠かさず出力を止めて警告する（FR-14）
- 代替フォントは端末に実在するものから構成する（Noto Sans JP の常駐を前提にしない）（FR-02）

**v0.2 の主な変更（2026-11-19 のレビュー反映）：**
- Google Fonts 連携（旧 FR-03）を不採用とした。日本語フォントは容量が大きく、静的アプリでの永続保存と相性が悪いため。フォント供給は端末フォント＋フリーフォントの取り込み（FR-04／FR-05）に一本化する
- 長文の分割出力（旧 FR-10）を不採用とした。Canvas の制約（最大寸法・面積）の中で設計し、上限を超える場合は警告を出す方式とする
- 横印刷モード（FR-14）を追加した
- 二値化出力（FR-15）を必須に昇格した。アルゴリズムはテキスト向けに大津の二値化を用いる
- 欠字（選んだフォントに無い文字）の検出・プレビュー強調・警告・代替フォント描画を FR-02 に明記した
- 保存ファイル名の規則（Voice2QR／MiniMapPrint／pic2gray4px と共通）を FR-09 に明記した
- 出力幅プリセットは px を主表記とし、dpi は括弧書きで補足する（FR-07）

## 1. プロジェクト概要

FontMemoは、ユーザーが自由にフォントを選択・追加し、入力した文字や文章を印刷用のPNG画像として出力するWebアプリケーションである。

主な用途は、Phomemoなどのサーマルプリンタで、標準アプリに用意されていないフォントを使った文字印刷を実現すること。

特に、従来の「別アプリで文章作成 → スクリーンショット撮影 → プリンタアプリで画像印刷」という煩雑な作業を解消する。文章は印刷幅で折り返して縦に長く出力でき、さらに横印刷モードでは文字を90度回転させ、紙送り方向に長く伸びるバナー状の出力もできる。

### 基本方針

- PC・スマートフォン双方に対応する。
- レスポンシブデザインを採用する。
- PWAとしてインストール可能にする。
- GitHub Pages等でホスティング可能な完全静的アプリとする。
- サーバー、ユーザー登録、クラウドデータベースは使用しない。
- 印刷は既存のプリンタアプリに任せる。
- 本アプリ自身にBluetooth印刷機能は実装しない。

## 2. 対応環境

### 2.1 プラットフォーム

- Windows、macOS、Linuxのモダンブラウザ
- Androidのモダンブラウザ
- iPhone・iPadのSafari等
- PWAとしてのホーム画面追加

### 2.2 対象プリンタ

特定メーカーに依存しない画像出力方式を採用する。

想定機種：

- Phomemoシリーズ
- Brother P-touch CUBEシリーズ
- Phomemo T02などの小型サーマルプリンタ
- その他、PNG画像の読み込みに対応するプリンタ・印刷アプリ

プリンタとの直接通信は行わない。

## 3. 機能要件

### FR-01 テキスト入力

**優先度：必須**

- 入力は WYSIWYG 編集欄で行う。実際のフォントで表示しながら書き、入力・文字選択・スタイル適用が1か所で完結する。
- スマホ標準の文字選択とコピー＆ペーストの操作はそのまま使えること（アプリ独自の選択 UI で置き換えない）。
- 日本語・英語・数字・記号を入力できる。
- 複数行の文章を入力できる。
- 明示的な改行を保持する。
- 印刷幅に合わせて自動折り返しを行う（プレビュー側）。
- 文章の長さは画面サイズに制約されない。
- 編集内容をプレビューに反映する。
- 入力文章は永続保存しない。
- 文章欄の表示サイズは「印刷フォントサイズ × 固定倍率」とし、倍率は ×1 で固定する（設定項目にしない）。行間は表示専用の固定値とする。印刷結果には影響しない。

入力文章は、ページの再読み込みや終了時に失われてもよい仕様とする。

### FR-02 フォント選択・フォント管理と欠字の扱い

**優先度：必須**

- フォントの選択はスタイル欄のプルダウンで行う（FR-16）。
- フォント管理画面で、同梱フォント・取り込みフォント（FR-04）・端末フォント（ブラウザ標準／端末の明朝／端末のゴシック）を一覧表示する。端末フォントの列挙（Local Font Access API）は前提にしない。
- 一覧の行を選択すると、そのフォントの見本（サンプル文字列）を表示する。同梱フォントは、画面を開いた時点では読み込まず、選択する操作で初めて読み込む。
- 一覧の各行に On/Off を設け、Off のフォントはスタイル欄に表示しない（使用中のフォントは除く）。On/Off の状態は保存する（FR-12）。
- 見本の場所から、そのフォントをそのまま全体フォントに設定できる。取り込みフォントは見本の場所から削除できる。
- 日本語フォントと欧文フォントに対応する。
- 選んだフォントに無い文字（欠字）がある場合、その文字をプレビュー上で強調表示し、警告メッセージを出す。
- **欠字検出の方式：** 取り込んだフォントについては、フォントファイル内部の `cmap` テーブルを解析して Unicode 文字とグリフの対応を調べ、正確に検出する。同梱フォントについては、ビルド時に同じ解析で生成した coverage manifest で判定する。`FontFaceSet.check()` はフォントの読み込み状態を確認する API であり、個別文字の収録判定には使えない（MDN 明記）。
- **検出の保証範囲：** 保証できるのは取り込みフォントと同梱フォントに対してのみ。端末フォント（OS標準フォント等）は文字収録情報を取得できないため、欠字検出の対象外とする。この範囲はアプリ内でも利用者に分かるようにする。
- 欠字は代替フォントで描画する。フォールバックチェーンは「選択フォント → 端末で利用可能な代替フォント（OS標準の日本語フォント等。Noto Sans JP は端末に存在する場合のみ）→ sans-serif」で構成し、存在しないフォント名を前提にしない。ユーザーが「その文字だけ違う書体になる」ことに気づけるのが目的であり、無言で化けたまま出力しない。
- 強調表示はプレビュー上のみとし、出力PNGには含めない。出力PNGでは欠字も代替フォントで通常描画する。

### FR-03 Google Fonts連携

**不採用（2026-11-19 決定）**

日本語フォントはフルセットで数MB級と大きく、Google Fonts の分割配信（unicode-range サブセット）を静的アプリ側で永続保存・オフライン再利用する設計と相性が悪い。またカタログ取得方式によってはAPIキーの埋め込みが必要になる。フォント供給は FR-04（取り込み）と FR-05（FONT FREE 連携）に一本化する。

### FR-04 外部フォントのインポート

**優先度：必須**

- ユーザーが入手したフォントファイルを読み込める。
- TTF形式に対応する。
- OTF形式に対応する。
- WOFF / WOFF2形式にも対応することを目標とする。
- ZIPファイルのまま取り込める。ZIP内のフォントは全件取り込み、重複は内容ハッシュで防ぐ。
- 追加したフォントをIndexedDBに保存する。
- 次回起動時に保存済みフォントを再登録する。
- フォントの削除に対応する。
- フォントファイルは外部サーバーに送信しない。

フォントファイルを使用する際のライセンスは、元の配布元の規約に従う。

### FR-05 FONT FREE連携

**優先度：必須**

FONT FREE（https://fontfree.me/）を利用するユーザーに対応する。

初期バージョンでは以下を実装する。

- FONT FREEへのリンクをフォント管理画面に設置する。
- FONT FREEで配布先を確認し、ユーザー自身がフォントを取得する。
- ダウンロードしたフォントファイルをFontMemoに取り込める。

FONT FREEの検索結果取得、スクレイピング、フォントの代理配布は行わない。

サイト掲載フォントの利用条件は各作者・配布元の規約に従う。

### FR-06 文字レイアウト設定

**優先度：必須**

以下の設定項目を設ける。

- フォント（スタイル欄で選択する）
- 文字サイズ（スタイル欄で設定する。範囲ごとの大きさは FR-16）
- 行間
- 上下左右の余白
- 左揃え・中央揃え・右揃え（段落ごとに指定できる。操作はスタイル欄で行い、カーソルのある段落、または選択範囲が触れる段落すべてに適用する。指定のない段落は既定のそろえに従う）
- 画像の横幅
- 白背景・黒文字

文字サイズ・行間・余白は数値またはスライダー等で調整できる。

設定変更はリアルタイムプレビューに反映する。

印刷の向き（通常／横）は FR-14 で扱う。

### FR-07 印刷幅設定

**優先度：必須**

以下の出力幅をプリセットとして提供する。表記は px を主とし、dpi は括弧書きで補足する（他の設定が px 単位のため、幅だけ dpi 表記にすると混乱する）。

- 250px
- 384px（200dpi相当、T02など）
- 576px（300dpi相当、M02Sなど）
- 任意のカスタム幅

出力画像の高さは文章量に応じて自動決定する（上限については FR-09 を参照）。

具体的なプリンタ対応幅は実機検証により調整する。

### FR-08 編集欄によるプレビュー（旧：プレビュー）

**優先度：必須**

- 独立したプレビュー欄は設けない。編集欄がプレビューを兼ね、入力したままのレイアウトで印刷される（アプリ v0.5.0 で改訂。v0.3.0 までは独立プレビュー）。
- 編集欄の表示倍率は、印刷幅（FR-07）が画面の表示幅に収まるよう動的に決める。表示寸法と実際の出力ピクセル数は、この表示倍率と実解像度の分離として保つ。
- フォント、文字サイズ、改行、余白、段落ごとのそろえを、印刷レイアウトどおりに編集欄で再現する。
- 欠字の強調表示（FR-02）は編集欄の中で行う。
- 横印刷モードでは、編集欄は読み向きのブロック表示とし、高さが紙幅に収まる形で示す。回転は出力時に行う。
- 画像出力時に文字が欠けないようにする。

### FR-09 PNG画像出力

**優先度：必須**

- 文章全体をPNG画像に変換する。
- スクリーンショット方式を使用しない。
- ブラウザ上で直接画像を生成する。
- 複数行・長文に対応する。
- 指定した横幅で生成する。
- 画像の高さは内容から自動計算する。
- PNGファイルをユーザーの端末に保存できる。
- 保存と共有（プリンタアプリへの受け渡し）の両経路を用意する。保存・共有ボタンはプレビューの直下に配置する。
- 共有は HTTPS 等の対応環境でのみ動作する。共有できない環境では、無言で失敗せず「共有できないので PNG 保存を使ってください」と表示する。
- サーバーへの画像アップロードを行わない。
- 出力PNGは FR-15 により二値化する。

**出力サイズの上限：** Canvas の最大寸法・最大面積はブラウザ・端末ごとに異なる（iOS では 4,096×4,096px の制限が MDN に明記されており、超過すると描画が成立しない）。上限は固定値にせずプラットフォーム別の保守値とし（初期値：iOS 4,096px／その他 8,192px、いずれも長辺。実機検証で確定する）、分割出力は行わない（旧 FR-10 不採用）。**上限を超える場合は出力を生成せず**、警告を表示して「全文は出力されない」ことを明確に伝え、文字サイズを下げる・文章を短くする等の対処を促す。本アプリは「スクリーンショットに収まらない長文を画像にしたい」という依頼から始まっているため、末尾を切り捨てた画像を利用者の確認なしに保存することはしない。

**保存ファイル名（他3アプリと共通の規則、2026-11-19）：** デフォルト名は `fontmemo-YYYYMMDD-HHMMSS.png`（ローカル時刻、秒まで）。Web アプリからは保存先に同名ファイルがあるか確認できないため、名前自体で衝突を避ける。同一セッションで同名が再生成されたら末尾に `-2`、`-3` を付ける（Voice2QR／MiniMapPrint／pic2gray4px と同一規則で、FontMemo を含め4アプリ共通）。

### FR-10 長文の分割出力

**不採用（2026-11-19 決定）**

Canvas の制約があるなら、その制約の中で設計する。長文への対応は FR-09 の上限＋警告で扱う。

### FR-11 フォントの永続保存

**優先度：必須**

追加したフォントはIndexedDBへ保存する。

保存対象：

- フォントファイルのバイナリデータ
- フォント名
- フォント形式
- フォント識別ID
- 入手元などの任意メタデータ

起動時に保存済みフォントを読み込み、FontFace APIを用いて利用可能にする。

フォント管理画面から削除できるようにする。

### FR-12 アプリ設定保存

**優先度：必須**

以下の設定をlocalStorage等に保存する。

- 最後に使用したフォント
- 文字サイズ
- 行間
- 余白
- 文字揃え
- 出力画像幅
- 印刷の向き（FR-14）
- その他のUI設定

入力文章そのものは保存対象としない。

### FR-13 オフライン動作

**優先度：必須**

- Service Workerによるアプリ本体のキャッシュ
- PWAのマニフェスト
- インストール可能な構成
- 保存済みフォントによるオフライン編集
- オフラインPNG出力

新しいフォントの取得やFONT FREEの閲覧にはネットワーク接続が必要。

### FR-14 横印刷モード

**優先度：必須（2026-11-19 追加）**

- 印刷の向きとして「通常」と「横」を選べる。
- 横モードでは、文字を読み向きのまま「幅＝文章の長さ方向、高さ＝行数×行間」のキャンバスに描き、出力時に90度右回転させる。紙幅に収まるのは行ブロックの高さのほうで、文章は紙送り方向に長く伸びる（バナー／リボン状の印刷を想定）。
- 横モードの「画像の幅」は印刷幅（紙幅）そのものである。行ブロックの高さは紙幅ちょうどとし、行が少ない場合は余りが白になる。回転後の画像の幅は常に紙幅と一致する（通常モードで画像幅がプリセットと一致するのと同じ契約）。
- 右回転のため、文頭が画像の上端に来て、印刷では文頭から先に出る。
- 行ブロックの高さ（行数×行間＋余白）が出力幅を超える場合は、**出力を生成せず**警告を表示し、文字サイズ・行数・余白の変更を促す。黙って文字を欠かさない。
- 長さ方向の上限は FR-09 の長辺上限と同じ扱いとする。
- プレビューは回転後の縦長画像で表示する（FR-08）。
- 縦書き（縦組み）とは別機能であり、本モードは横書き文章の回転である。

### FR-15 二値化出力

**優先度：必須（2026-11-19 追加）**

- フォントのアウトラインはベクタであり、Canvas 描画時に縁がアンチエイリアス（グレー）になる。サーマルプリンタは二値しか出せないため、書き出し側で二値化する。プリンタアプリ側の写真向け変換に任せると細い線が痩せたり潰れたりしやすい。
- アルゴリズムはテキストに適した**大津の二値化**（濃度ヒストグラムの二峰性から閾値を自動決定）を用いる。写真向けの誤差拡散（ディザ）は、文字の細線を点描化して潰すため採用しない（pic2gray4px の方式に縛られない）。
- 二値化は出力PNGに対して常時適用する。

### FR-16 部分書式（範囲スタイル）とスタイル欄

**優先度：必須（v0.4 で追加。v0.2.0 で実装）**

- 文章の文字範囲ごとに、フォント・大きさ・太字・斜体を指定できる。
- 大きさは絶対 px で指定する（全体フォントサイズに対する倍率の概念は持たない）。全体の文字サイズを後から変えても、範囲の大きさは変わらない。
- 太字・斜体は、そのフォントファミリーに実フェイス（Bold／Italic）が含まれている場合のみ指定できる。無い場合は合成しない。
- スタイルの適用はスタイル欄で行う。スタイル欄は常時アクティブとし、範囲を選択しているときはその範囲へ、選択していないときは全体のデフォルト（フォント・文字サイズ・太字・斜体）へ作用する。
- モバイルではコントロール操作でブラウザの選択が崩れるため、アプリ側で最後の選択範囲を保持し、保持した範囲に適用する。スマホ標準の選択・コピー＆ペースト自体には干渉しない（FR-01）。
- スタイルのクリア（範囲の指定を全て外す）操作を用意する。

## 5. データ保存設計

### 5.1 保存方針

FontMemoは文章管理アプリではないため、入力文章は永続保存しない。

保存するのは、ユーザーが追加したフォントとアプリの表示・出力設定のみとする。

### 5.2 保存領域

| データ | 保存先 |
|---|---|
| 追加フォント本体 | IndexedDB |
| フォントメタデータ | IndexedDB |
| アプリ設定 | localStorage |
| 入力中の文章 | 実行時メモリ |
| 出力したPNG | ユーザー指定のファイル保存先 |
| アプリ本体 | Service Worker / Cache Storage |

### 5.3 データの扱い

- フォントはブラウザのサイトデータ削除によって失われる可能性がある。
- 初期版ではフォントのクラウド同期を提供しない。
- ブラウザ間・端末間でフォントを自動共有しない。
- フォントは必要に応じて再インポートできる。
- ユーザーの文章やフォントをサーバーへ送信しない。

## 7. ライセンス・権利関係

### フォント全般

- Google Fonts 連携は不採用としたため、対象外（FR-03）。
- 取り込むフォントはユーザー自身が配布元から取得したものとし、各フォントの利用条件は配布元に従う。
- 商用利用可否とフォントファイル再配布可否は区別する。
- アプリ側はユーザーが選択したフォントを端末内で読み込む。

### FONT FREEおよび外部フォント

- FONT FREEはフォントの紹介サイトとして利用する。
- フォントファイルの代理配布は行わない。
- 各フォントの利用条件は配布元に従う。

### アプリ名称

アプリ名は「FontMemo」とする。

日本のJ-PlatPatでユーザーが商標検索を実施し、該当する完全一致登録が0件であったことを確認済み。

商標の包括的な非侵害保証を意味するものではない。

## 8. UI/UX方針

### ターゲットと世界観

- 主な利用者は若い女性層を想定する。シンプルで迷わない操作であることが前提（考えなくても保存までたどり着けること）。
- 世界観は「エモい」ことを重視する。ピンク色への固定はしない。くすみカラーやミルクティー系など、柔らかく感情に寄る配色と、丸みのある形状、フォント見本が映える余白で設計する。具体的なアートディレクションは実装時にモックで提示して決定する。

### PC

画面を左右に分割する。

- 左側：文章入力、フォント選択、各種設定
- 右側：印刷プレビュー、画像保存

### スマートフォン

縦方向のレスポンシブレイアウトとする。並びは以下の順とする。

- スタイル欄（フォント・大きさ・太字・斜体）
- 文章入力（WYSIWYG 編集欄）
- レイアウト設定
- プレビュー
- PNG保存・共有（プレビュー直下）
- フォント管理

頻繁に操作する項目へ簡単にアクセスできる構成にする。

### 設計思想

- シンプルな操作
- 文章をすばやく画像化
- 好きなフォントを簡単に追加
- 長文でもスクリーンショット不要
- 印刷機種に依存しない
- オフラインでも利用できる
- ユーザーのデータを外部送信しない

## 9. 非機能要件

### 性能

- フォントや設定の変更を速やかにプレビューへ反映する。
- 長文画像出力時にブラウザのメモリ負荷を考慮する。
- 大容量の日本語フォントを初回起動時に一括取得しない。

### 互換性

- PC・スマートフォン両対応
- マウス・タッチ操作に対応
- ブラウザ固有機能への依存を最小限にする

### 安全性

- 入力テキストを外部サーバーへ送信しない。
- 取り込んだフォントの形式・容量を検証する。
- 破損したフォントによる処理失敗を適切に扱う。
- 保存容量不足時にエラーを表示する。

## 10. 初期リリースの完成条件

以下を満たした時点でv1.0としてリリース可能とする。

1. PCとスマートフォンで操作できる。
2. FONT FREEなどで取得したTTF/OTFフォントを追加できる。
3. 追加フォントがブラウザ再起動後も利用できる。
4. 日本語長文を入力・編集できる。
5. 文字サイズ、行間、余白、配置を変更できる。配置（そろえ）は段落ごとに変更できる。文章の一部だけフォント・大きさ・太字・斜体も変更できる（太字・斜体は実フェイスのあるフォントのみ）。
5b. フォント管理で同梱・取り込み・端末フォントを一覧でき、見本の確認と On/Off の切り替えができる。
6. 指定した横幅で画像プレビューできる（幅は px 主表記＋dpi 括弧補足）。
7. 横印刷モードで、回転済みの縦長プレビューとPNG出力ができる。
8. 出力PNGが二値化されている（テキスト向けの大津法）。
9. 選んだフォントに無い文字がプレビューで強調され、警告が出る（検出の保証は取り込みフォントに対して）。出力では代替フォントで描かれる。
10. 長文をPNG画像として保存できる（長辺上限を超える場合は警告が出て、欠けた画像は生成されない）。
11. 保存ファイル名が他3アプリと共通の規則（FontMemo を含め4アプリ共通）に従う。
12. オフラインで保存済みフォントを利用できる。
13. 入力テキストが永続保存されない。
14. GitHub Pagesで正常動作する。

## 11. 今後の設計・検証事項

- フォントのブラウザ別互換性
- フォント追加時のライセンス情報の扱い
- 初回起動時（取り込みフォントが無い状態）の体験：端末フォントのみで始まるため、再配布可能なフリーフォントの同梱を検討するか

- 欠字検出（cmap 解析）の実装方式と検証：対応フォーマット（TTF/OTF/WOFF/WOFF2）ごとの cmap 取得可否

- iOS/Androidでの画像保存方式
- 印刷アプリ側の長大画像読み込み制限
- 出力画像の適切な余白・DPI設定

**基本方針：シンプルで軽量なフォント画像生成PWAとして開発し、文章管理機能やプリンタ直接制御は実装しない。**
